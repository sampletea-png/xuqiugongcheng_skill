# 整理方法

用脚本把方法写成临时 Markdown。一个项目里的 Java、TypeScript、JavaScript、Vue 一起整理。每个方法单独一个文件，放在与源文件相同的相对目录下。

「做了什么」整理时不写。文件里先放「尚未填写」。只有接下来的任务要用到某个方法的「做了什么」时，才读源码补上这一份。

使用本技能前先安装。安装把一段规则写入项目根的 `AGENTS.md`，并立刻做一次初始化。此后新增、修改或删除源码时，按 `AGENTS.md` 里的命令再执行脚本。

## 步骤

1. 这份说明所在的目录是本技能目录。对目标项目执行：

```text
node <本技能目录>/scripts/install.mjs --project <项目根>
```

安装在 `AGENTS.md` 的 `<!-- catalog-methods:start -->` 与 `<!-- catalog-methods:end -->` 之间写入更新命令。已有这对标记时只替换这一段，其余内容保留。标记不完整就停下。写入的命令是：

```text
node <本技能目录>/scripts/catalog.mjs --project <项目根>
```

省略 `--project` 时用当前目录。只查看一部分时可另加 `--dir <相对目录>`、`--package <包或目录前缀>` 或 `--class <类名>`，这不能代替 `AGENTS.md` 里的全量命令。调用方仍在整个项目源码里查找。

脚本会在本技能目录安装依赖。项目里有 `.java` 时使用本机 JDK。源码有错误时，能确定的方法仍写入。

2. 脚本按源文件的 SHA-256 更新 `.scratch/方法/`。这个目录是临时产物，不写进源码目录。每个方法文件里的「源文件哈希」就是生成它时源文件全部字节的 SHA-256。

- 与上次记录的 SHA-256 相同：跳过这些方法文件，不改内容。
- 不同，或上次没有这份源文件：删掉该源文件已经生成的方法文件，再按当前源码重新生成。重新生成的「做了什么」写「尚未填写」。
- 遍历结束后，没有被跳过、也没有被重新生成碰到的方法文件是脏文件，删掉。源文件或其中的方法已经不在时，就会落在这里。

全部源文件都没变时，不再解析源码。有文件要重写时，仍解析当前全部源码，但只改写变过的源文件对应的方法文件。没变的文件里，「被使用」要等它自己的源文件发生变化才会更新。只加了 `--class` 或 `--package` 时，变过的源文件不会记成已更新；之后再执行一次不带这两个参数的脚本，这份源文件里其余方法才会重写。

3. 要用某个方法的「做了什么」，而那一份还是「尚未填写」时：按该文件的「源文件」和「源码范围」读取方法，写成一段，替换「尚未填写」。保留身份、调用关系、宿主、位置、源文件哈希和 `<!-- body:... -->`。方法体是空的，写「方法体是空的」。只有声明，写「只有声明，没有方法体」。不逐行翻译源码，不复述方法名，不把「使用了」再抄一遍，不写没有依据的目的。

脚本失败就停下，不改用手写扫描。

## 方法

具名方法：写在有名字的类型上、自身也有名字的方法，包括构造方法。构造方法的方法名写类型名，种类写「具名 · 构造」。TypeScript、JavaScript、Vue 里，模块顶层的具名函数，以及赋给具名绑定的函数，也按具名方法写。它们的类写源文件名，不含扩展名。对象字面量上的方法，类写那个对象的名字。

匿名方法：lambda、箭头函数、匿名函数，以及写在匿名类型上的方法。类取最近的有名字的外层类型。没有方法名时，方法名写「匿名」。

同一类型上同名不同参数的方法分开写。重写或实现接口本身不算使用，只有调用才算。

Java 的包路径是包名。TypeScript、JavaScript、Vue 没有包声明时，包路径是源文件相对项目根的目录，分隔符用 `/`。

每个方法一个身份：

- 具名：`<包路径>.<类>#<方法名>(<参数类型>)`
- 匿名：`<包路径>.<类>#<宿主身份>@<相对路径>:<起始行>:<起始列>`
- 匿名类型上还有方法名时，末尾再加 `#<方法名>(<参数类型>)`

字段、静态块、实例初始化块和 Vue 模板里的匿名方法，宿主写成字段名、`clinit`、`init块` 或 `模板`。这些宿主不单独成文件。源码里没有写出的默认构造方法也不单独成文件；调用它时只写身份。

## 调用

「使用了」只记该方法体内看见的直接调用、方法引用，以及该方法体内定义的匿名方法。写在匿名方法体内的调用，记在那个匿名方法上。

「被使用」只记项目源码里另一具名方法或匿名方法对它的调用。

项目外的方法不写进方法文件。调用它们时写「项目外」。目标看不清时写「未能解析」。

依赖目录、构建产物，以及明确由工具生成的代码不整理。

## 文件

目录与源文件相对项目根的目录一致。`com/a/b/c/X.java` 里的方法写成：

`.scratch/方法/com/a/b/c/X-<方法名>.md`

同一目录里还有别的源文件时，文件名仍以各自的源文件名开头，避免互相覆盖。重载把参数类型接在方法名后面。匿名方法用 `匿名-<起始行>-<起始列>`。

```markdown
# <方法名>

方法：<方法名>
类：<类>
包路径：<包路径>
种类：具名
身份：`<身份>`
源文件：<相对路径>
源文件哈希：<该源文件全部字节的 SHA-256>
源码范围：<起始行>-<结束行>
<!-- body:<方法正文摘要> -->

## 做了什么

尚未填写

## 被使用

- 具名 · `<身份>`
- 匿名 · `<身份>`

## 使用了

- 具名 · `<身份>`
- 匿名 · `<身份>`
- 项目外 · `<源码里看见的调用>`
- 未能解析 · `<源码里看见的调用>`
```

种类是「具名」「具名 · 构造」或「匿名」。匿名方法在身份下再写 `宿主：` 和 `位置：<相对路径>:<起始行>:<起始列>`。某一节没有条目时，只写「没有」。

## 示例

`submit` 的方法体里定义了一个 lambda。这个 lambda 调用 `audit`。`submit` 调用 `save`，并使用这个 lambda。

- `submit` 使用了这个匿名方法，以及 `save`
- 这个匿名方法使用了 `audit`
- `audit` 被这个匿名方法使用
- `save` 被 `submit` 使用

## 不做

- 不修改、不格式化、不重构源码
- 整理时不填写「做了什么」
- 不评价实现，不建议改名或合并方法
- 不把字段初始化、静态块或类型声明记成方法
- 不把项目外的方法写进方法文件
- 不把源码里没有写出的默认构造方法写进这份文件
- 不把方法文件写进源码目录；临时文件只放在 `.scratch/方法/`
- 不猜测未能解析的调用目标
- 脚本失败时不改用手写扫描
- 不改写 `AGENTS.md` 里整理方法标记以外的内容
- 不写需求、地图或票
