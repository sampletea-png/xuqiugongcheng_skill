# 对齐原话

开始对齐前，先读取项目的领域术语。后面的重述、询问和用词都优先用这些词。已经有术语的概念，不另造叫法。

默认读取仓库根目录的 `CONTEXT.md`。项目用 `CONTEXT-MAP.md` 或另行写明了术语文件的位置时，以项目写明的那份为准。两份都有时一起用。同一个词两边都有定义时，用项目自定义的那份。已确认的新词仍按后文「术语文件」写入。

本技能对齐一句原话。原话保留。理解分成两段，都由说出原话的人确认或改正。第一段只复述原话里有的内容。某一轮复述确认之后，再询问会改写这句话含义的事项。询问前先探索，事实写下来，只有对方能拍板的才问，一次一题。两段和术语都确认之前，不写结论。

默认父目录是 `.scratch/会话对齐/<会话名称>/`。其下是 `对齐/<对齐名称>/`。路径用文本：会话名称、对齐名称。对齐 UUID 和会话 UUID 写在正文里，不放进路径。

引用本技能的技能，或这一轮启用本技能的提示词，可以写明三件事：父目录、开头额外行、额外阅读。写明是明确写出这一次对齐用哪一个父目录、开头要加哪些行、还要读哪些文件。话里或上下文里仅仅出现某个路径，不算写明。每一项各自取值：提示词写明了就用提示词的，否则用那份技能写明的，都没有就用默认。默认没有开头额外行，也没有额外阅读。只要求执行另一份技能、并没有写明这三项的技能，不算写明。

指定的父目录必须已经存在。它不存在，或写明它的那一方已经停下，本技能停下，不改用默认父目录，也不创建那个父目录。

已确认的词写入仓库根目录的 `CONTEXT.md`。这是项目级术语。有 `CONTEXT-MAP.md` 时，写入它指向的那份。这里不写对齐 UUID、会话 UUID、会话名称，也不写开头额外行。

## 步骤

1. 按上面的次序选定父目录。用默认父目录时，文件写会话名称。用指定的父目录时，不写会话名称，也不创建 `.scratch/会话对齐/`。
2. 本会话若还没有会话 UUID，就运行本技能目录下的 `scripts/new-uuid.ps1` 取得一个，并在本会话中一直持有。再运行一次该脚本，取得对齐 UUID 并持有它。两次都把当前仓库根目录传给脚本。脚本会读取 `.scratch` 下 Markdown 文件里、第一个二级标题之前的 UUID 字段。对齐 UUID 不是会话 UUID。此后本会话未关闭的对齐，就是会话 UUID 与本会话相同、对齐 UUID 由本会话持有、且状态为正在对齐的那些。不要自行另造 UUID。
3. 使用默认父目录、且本会话还没有会话名称时，从这次会话正在做的事取出短文本，本会话一直持有。不要每次对齐都另取。还没有更宽的事可指时，用这句原话的短文本，它可以与对齐名称相同。`.scratch/会话对齐/<会话名称>/` 已存在，且其中过程文件的会话 UUID 与本会话不同时，更换这次的会话名称，会话 UUID 不变。使用指定的父目录时，不取会话名称。
4. 从原话取出对齐名称，作为短文本。在父目录下创建 `对齐/<对齐名称>/过程.md`。写入对齐 UUID、会话 UUID、对齐名称、开始时间、状态「正在对齐」，以及原话。使用默认父目录时加写会话名称。有开头额外行时，把那些行原样写在会话 UUID 之后；有会话名称时，会话名称写在额外行之前。开始时间用来区分各次对齐何时开始。同一父目录下已有相同对齐名称时，改这次还没写完的对齐名称，对齐 UUID 不变。
5. 用自己的话写一轮重述，只含原话里有的内容，状态为未确认。
6. 原话和这一轮重述并排交给对方。对方确认、改正或否定。
7. 改正或否定就再追加一轮，直到某一轮被确认。
8. 某一轮重述已确认后，先探索，再询问。探索只读：开头写明的领域术语、同一父目录下其他对齐的过程与结论、写明的额外阅读、这句原话和已确认的重述。没有额外阅读时，不另找文件。推得出的事实写入过程文件的「探索」。事实不向对方提问。

   一题要同时满足三条才问：只有对方能拍板；不依赖还没回答的题；换一个答案，这句话就变成另一件工作，或变成另一个主张。原话没说清、互相矛盾，或一个词有两种指称，并且第三条成立，才属于这里。今后的决定也要第三条成立才问。

   一次只问同时满足三条的一题。用「交给对方的一题」那个外形交给对方，并把同一题写入「询问」，状态为未确认。对方回答之前，不问下一题，也不进入术语。至少给出 (a)(b)(c)：推荐答案和另外两个备选。推荐是其中一项，用 ➡️ 标出。问句写成回答「是」就接受推荐。背景和为什么问都是为了让对方理解这一问、知道怎样回答。有的题没有背景就无法理解，也不知道如何回答。背景写提问时的处境：这句话的哪一处没说清，或哪一个今后的决定已经挂在这句话上。为什么问写这一问要解决的问题：不先定它，已确认的重述仍有哪几种含义。每个答案都写简短思考步骤、选择它的理由，以及它怎样解决这个问题。怎样解决把这一项讲清楚，使对方按正确的理解来选。

   对方选定一项，或给出自己的答案，就把选择记下，状态改为已确认。对方否定这一题，选择写「不成立」，状态改为已否定。已写下的答案不覆盖。被否定的题不进入结论。

   这一题有了已确认或已否定之后，再看还有没有同时满足三条的题。没有就停止。一题都没有时，「询问」写「无」。

   例如原话「我期望实现小说编辑器」。会问：小说编辑器是作者自己写一部小说，还是也包含编辑审稿。会问是因为两个答案让这句话分别指一件工作和两件工作。不问正文按章保存还是按整部保存；原话没有出现章或保存。原话里已经出现章或保存时，这一问才成立。
9. 从原话、最后一轮已确认的重述、以及状态为已确认的询问选择里，抽出可能有多种指称的词。每个词在 `过程.md` 里记下：指什么、不指什么、其他叫法、谁这样用，状态为未确认。同一种写法有两种指称时，收成两个词。已否定的询问不抽。
10. 对方逐条确认这些词。没有需要对齐的词时，跳过这一步。
11. 最后一轮重述已确认，该问的题都已是已确认或已否定，抽出的词都已确认之后，把术语写入 `CONTEXT.md`，并在同一对齐目录写 `结论.md`。然后把过程状态改为「对齐完毕」。在那之前不写这两份。

重新查看时，打开这次使用的父目录下的 `对齐/`。目录名是对齐名称。读每个 `过程.md` 开头的原话、开始时间、状态和会话 UUID。默认父目录的会话名称是 `.scratch/会话对齐/` 的下一级。

为什么问：<为了理解这一问。要解决的问题：不先定它，已确认的重述仍有哪几种含义。>

(a) <答案>

思考：<简短思考步骤。>
理由：<选择这一项的理由。>
怎样解决：<这一项怎样解决为什么问里的问题。把这一项讲清楚，使对方按正确的理解来选。>

`.scratch/会话对齐/<会话名称>/对齐/<对齐名称>/过程.md`

过程状态只有正在对齐、对齐完毕。重述的状态只有未确认、已确认、已否定。询问的状态只有未确认、已确认、已否定。术语的状态只有未确认、已确认。改正不覆盖已写下的轮次或题目。

## 术语文件

已确认的词写入仓库根目录的 `CONTEXT.md`。已有 `CONTEXT-MAP.md` 时，写入它指向的那份 `CONTEXT.md`。文件不存在就在第一个词确认时创建。这里不写对齐 UUID、会话 UUID、会话名称，也不写开头额外行。

`CONTEXT.md` 只放术语。定义写它是什么，一两句。不写它做什么，不写实现，不写重述过程，不写询问。

```markdown
# <这一语境的名称>

<这一语境是什么，一两句。>

## Language

**<词>**:
<它是什么。>
_Avoid_: <放弃的叫法；没有则省略这一行>
```

## 结论文件

结论与过程放在同一对齐目录。这是临时文件。`CONTEXT.md` 不随这些临时文件删除。开头与过程文件相同：使用默认父目录时写会话名称；有开头额外行时原样写入。

```markdown
# 对齐结论

对齐 UUID：<与过程文件相同。>
会话 UUID：<与过程文件相同。>
会话名称：<与过程文件相同。使用默认父目录时才写。>
<开头额外行。没有则省略。>

## 原话

<与过程文件相同。>

## 原话结论

<最后一轮已确认的重述。>

## 已确认的询问

- 问题：<问句>
  选择：<已确认的选择。对方自己给出的答案照实写。>
```

没有已确认的询问时，这一节写「无」。

此后若再改正，把过程状态改回「正在对齐」。重述有改正，就追加一轮重述。询问有改正，就追加一题，并写明改正的是哪一题。新的已确认重述替换「原话结论」。被改正的询问在「已确认的询问」里换成新题的选择。按确认结果改 `CONTEXT.md`，再把过程状态改回「对齐完毕」。原话不改。

## 不做

- 不把未确认的重述或未确认的询问写入 `结论.md`。
- 不把一次会话里的对齐集中写进 `.scratch/会话对齐/对齐/`。会话名称是中间那一层。
- 不把对齐 UUID 或会话 UUID 放进路径。
- 会话名称只在使用默认父目录时写入，并且只用作 `.scratch/会话对齐/` 的下一级目录名。对齐名称只用作 `对齐/` 的下一级目录名。
- 使用指定的父目录时，不写入 `.scratch/会话对齐/`。
- 指定的父目录不存在时，不改用默认父目录，也不创建那个目录。
- 不问不会改写这句原话含义的今后决定。
- 不一次问出多题。
- 不把探索到的事实拿去问对方。
- 不用会话名称或对齐名称判断两次对齐是不是同一次。同一次对齐看对齐 UUID。同一次会话看会话 UUID。
- 不用会话 UUID 或开头额外行里的 UUID 代替对齐 UUID。
- 不自行另造 UUID。
- 已经有领域术语的概念，不另造叫法。
- 不解释开头额外行。
