# 对齐原话

本技能只对齐一句原话。它会在需求工程里多次使用，也可以单独使用。原话保留。理解单独写出来，由说出原话的人确认或改正。确认之前不继续。

临时产物记在 `.scratch/需求工程/<需求名称>/`。路径用文本：需求名称、对齐名称。对齐的临时文件正文同时写需求 UUID、对齐 UUID、会话 UUID，三者都不放进路径。`CONTEXT.md` 仍是整个项目的持久化术语，不写这三个 UUID。

## 步骤

1. 确认临时目录 `.scratch/需求工程/<需求名称>/` 已经存在，且其中已有需求 UUID。没有需求名称时停止。
2. 本会话若还没有会话 UUID，就运行本技能目录下的 `scripts/new-uuid.ps1` 取得一个，并在本会话中一直持有。再运行一次该脚本，取得对齐 UUID 并持有它。两次都把当前仓库根目录传给脚本。对齐 UUID 不是需求 UUID，也不是会话 UUID。此后本会话未关闭的对齐，就是会话 UUID 与本会话相同、对齐 UUID 由本会话持有、且状态为正在对齐的那些。不要自行另造 UUID。
3. 从原话取出对齐名称，作为短文本。创建 `.scratch/需求工程/<需求名称>/对齐/<对齐名称>/过程.md`。写入需求 UUID、对齐 UUID、会话 UUID、对齐名称、开始时间、状态「正在对齐」，以及原话。开始时间用来区分各次对齐何时开始。同一需求下已有相同对齐名称时，改这次还没写完的对齐名称，对齐 UUID 不变。
4. 用自己的话写一轮重述，只含原话里有的内容，状态为未确认。
5. 原话和这一轮重述并排交给对方。对方确认、改正或否定。
6. 改正或否定就再追加一轮，直到某一轮被确认。
7. 从原话和这一轮已确认的重述里抽出可能有多种指称的词。每个词在 `过程.md` 里记下：指什么、不指什么、其他叫法、谁这样用，状态为未确认。同一种写法有两种指称时，收成两个词。
8. 对方逐条确认这些词。没有需要对齐的词时，跳过这一步。
9. 这一轮重述已确认，且抽出的词都已确认之后，把术语写入 `CONTEXT.md`，并在同一对齐目录写 `结论.md`。然后把过程状态改为「对齐完毕」。在那之前不写这两份。

重新查看时，打开该需求下的 `对齐/` 目录。目录名是对齐名称。读每个 `过程.md` 开头的原话、开始时间和状态。

## 过程文件

`.scratch/需求工程/<需求名称>/对齐/<对齐名称>/过程.md`

```markdown
# 对齐

对齐 UUID：<本会话为这次对齐生成并持有。>
需求 UUID：<这条需求临时文件里已有的 UUID。>
会话 UUID：<本会话生成并一直持有。同一次会话里的对齐写同一个。>
对齐名称：<短文本。也是本目录名。>
开始时间：<这次对齐开始的时间。>
状态：正在对齐

## 原话

<原样保留。>

## 重述

- 第 1 轮：<只含原话里有的内容。>
  状态：未确认

## 术语

- 词：
  指：
  不指：
  其他叫法：
  谁这样用：
  状态：未确认
```

过程状态只有正在对齐、对齐完毕。重述的状态只有未确认、已确认、已否定。术语的状态只有未确认、已确认。改正不覆盖上一轮。

## 术语文件

已确认的词写入仓库根目录的 `CONTEXT.md`。已有 `CONTEXT-MAP.md` 时，写入它指向的那份 `CONTEXT.md`。文件不存在就在第一个词确认时创建。这里不写需求 UUID、对齐 UUID 或会话 UUID。

`CONTEXT.md` 只放术语。定义写它是什么，一两句。不写它做什么，不写实现，不写重述过程。

```markdown
# <这一语境的名称>

<这一语境是什么，一两句。>

## Language

**<词>**:
<它是什么。>
_Avoid_: <放弃的叫法；没有则省略这一行>
```

## 结论文件

`.scratch/需求工程/<需求名称>/对齐/<对齐名称>/结论.md`

这是临时文件，和过程文件放在一起，整体任务结束后随该需求的临时目录删除。

```markdown
# 对齐结论

对齐 UUID：<与过程文件相同。>
需求 UUID：<与过程文件相同。>
会话 UUID：<与过程文件相同。>

## 原话

<与过程文件相同。>

## 结论

<最后一轮已确认的重述。>
```

此后若再改正，把过程状态改回「正在对齐」，在 `过程.md` 追加一轮。新的确认替换 `结论.md` 的结论，并按确认结果改 `CONTEXT.md`，再把过程状态改回「对齐完毕」。原话不改。

## 不做

- 不把未确认的重述写入 `结论.md` 或地图。
- 不把各次对齐集中写进 `.scratch/需求工程/对齐/`。
- 不把需求 UUID、对齐 UUID 或会话 UUID 放进路径。
- 不开始初始调研，不划边界，不建票。
- 不用需求名称或对齐名称判断两条原话是不是同一条需求。
- 不用需求 UUID 或会话 UUID 代替对齐 UUID。
